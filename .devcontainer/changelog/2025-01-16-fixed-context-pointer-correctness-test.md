# Fixed Context Pointer Correctness Test - January 16, 2025

## Problem
The `test_context_pointer_correctness` test in `tests/test-numa-coordinator.cpp` was failing because it used hardcoded expected values that didn't match the actual runtime values generated by the test framework.

## Root Cause
The test was expecting specific hardcoded values (5001 and 6001) but the actual test counters were created with different base values using the `create_isolated_counter` function which generates random unique values to prevent memory reuse issues:

```cpp
static int unique_counter = 0;
int unique_value = (++unique_counter) * 1000 + (rand() % 100);
int final_value = base_value + unique_value;
```

So the counters didn't start with the base values 5000 and 6000, but with much higher values after adding the unique offset.

## Solution
Fixed the test by:

1. **Dynamic Expected Value Calculation**: Instead of hardcoding expected values, the test now reads the actual initial values and calculates the expected values dynamically:
   ```cpp
   // Store the initial values for verification
   int initial1 = *counter1;
   int initial2 = *counter2;
   int expected1 = initial1 + 1;  // Work function increments by 1
   int expected2 = initial2 + 1;
   ```

2. **Fixed Comparison Logic**: Updated the comparison to use the dynamically calculated expected values:
   ```cpp
   if (*counter1 == expected1 && *counter2 == expected2) {
       printf("  ✅ Multiple context test: PASS (both contexts preserved)\n");
       printf("  🔍 Verification: No cross-contamination, different addresses preserved\n");
   } else {
       printf("  ❌ Multiple context test: FAIL (expected %d,%d, got %d,%d)\n", 
              expected1, expected2, *counter1, *counter2);
       all_tests_passed = false;
   }
   ```
